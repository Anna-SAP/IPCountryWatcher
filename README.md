# IP 国旗监视器（Windows 11）

[![Windows build](https://github.com/Anna-SAP/IPCountryWatcher/actions/workflows/build.yml/badge.svg)](https://github.com/Anna-SAP/IPCountryWatcher/actions/workflows/build.yml)

[下载安装程序](https://github.com/Anna-SAP/IPCountryWatcher/releases/latest/download/IPCountryWatcher-Setup.exe) · [下载便携版](https://github.com/Anna-SAP/IPCountryWatcher/releases/latest/download/IPCountryWatcher-portable.zip) · [最新发布](https://github.com/Anna-SAP/IPCountryWatcher/releases/latest)



原生 Windows 系统托盘应用。自动获取本程序的公网出口 IP，识别国家 / 地区，并把国旗显示在任务栏右下角。

## 本次更新（1.0.22）

以下为最新版本的变化；历次版本的主要变化与改进见[版本更新记录](#版本更新记录)。

- **新增约 2 秒一次的链路检测**：向 icanhazip 的解析地址、1.1.1.1、8.8.8.8 的 443 端口做 TCP 握手（不发送数据），并对比当前出口网卡（VPN 在线时即隧道网卡）的收发包计数。VPN 客户端仍显示“已连接”、隧道却已不回包时，通常 4–8 秒内即标红，不必等 VPN 客户端自己的看门狗（Surfshark 约需 25–50 秒）。
- **先复核再标红**：单次握手失败、或单轮 HTTPS 检测全部失败，只显示黄色 `!` 并立即复核；链路连续多轮无响应、或连续两轮 HTTPS 检测全部失败，才显示红色 `×`。中断后需持续正常 6 秒才取消提示。
- **线路质量预警**：近 20 轮握手丢失 ≥10%，或握手耗时中位数超过本线路基线的 2 倍时，显示黄色 `!`；菜单给出握手耗时、基线和丢失比例。
- **请求更省、更稳**：查询与检测复用 HTTPS 长连接，网络或代理变化、链路恢复时立即重建。超时与备用请求的启动时机按本线路近期实际耗时调整，慢但仍在响应的线路不再被误判为失败。
- **事件日志跨重启保留**：链路中断、恢复、质量下降和线路切换写入本地 `incidents.log`，中断时自动附上当时的检测记录；“导出连接诊断…”会一并导出最近的事件日志。
- **连接异常播报跟随红色判定**：链路中断时立即播报“网络连接异常”，不必等公网 IP 过期；单轮检测失败只在复核仍失败、角标变红后才播报。

| 托盘显示 | 含义 |
| --- | --- |
| 国旗，无角标 | 近期确认了本程序的出口 IP，两个连接检测服务均可达，链路检测正常或暂无法判断，国家信息无需过期缓存回退。 |
| 国旗或地球 + 黄色 `!` | 正在复核（单次握手失败或单轮检测全部失败）、链路恢复中、线路质量下降、结果已过期、仅部分检测可达，或国家缓存待更新；悬停可查看具体状态。 |
| 国旗或地球 + 红色 `×` | 链路连续多轮无响应（含“只发不收”），或连续两轮所测连接均未确认；将自动重试，保留的国旗仅供查看上次结果。 |
| 地球，无角标 | 连接检测可达且已确认 IP，但国家尚未识别；地球本身不等于系统断网。 |

**国旗表示出口所在国家，角标表示本程序的检测状态。** 检测成功不保证微信等其他应用、所有网站、IPv4 与 IPv6 或 VPN 加密通道都正常；检测失败也不等于已经证实整台电脑断网。

## 直接使用

双击 **bin/IPCountryWatcher.exe**。无需管理员权限，无需安装 Python 或 .NET SDK。发布时请保留同目录的 .exe.config、说明文件和四个 Probe / ProbeHost 组件。
如果未看见图标，展开右下角的隐藏图标区域；可以把图标拖到任务栏，或在 Windows 的任务栏设置中启用其显示。应用不能强制绕过 Windows 的托盘折叠设置。

- 悬停：查看连接检测状态、国家代码和公网 IP；历史结果会标注为“上次”。
- 右键：查看详细状态、手动刷新、复制近期确认的 IP、导出连接诊断、设置检查间隔、切换系统代理、开关国家 / 地区变化通知、设置语音播报、设置开机启动、重启应用、退出。
- 双击：立即触发刷新。
- 首次启动以地球加黄色角标等待检查。手动刷新、网络切换或短暂查询失败时，历史国旗最多保留到上次确认后的 2 分钟，同时立即显示相应连接角标；悬停与菜单明确标注“待确认 / 上次”。只有本轮确认且不足 30 秒的 IP 可以复制，历史结果不能复制为当前 IP。
- IP 或连接检测超过 30 秒未重新确认，即使下一轮查询仍在等待，也不会继续显示无角标的正常国旗。Windows 报告网络不可用、切换系统代理选项或睡眠恢复时立即清除历史国旗；确认 IP 已变但国家未知、或超过保留期时也显示地球，连接角标仍按检测结果显示。
- 变化通知仅在国家 / 地区改变时弹出，列出前后国家与 IP；同一国家 / 地区内更换出口 IP（如公司代理按目标网站选择出口）只更新悬停与菜单。新 IP 的国家尚未识别时先不通知，识别后再与上次确认的国家比较；断网或查询失败不会清除该基准。
- 开机启动默认关闭，开启后仅写入当前用户的 Run 注册表项。移动程序后请重新关闭、开启此选项。

## 语音播报

公网 IP 或国旗变化时，用简体中文女声播报，例如“网络出口已从新加坡切换到日本，新的 IP 是一零三点二五点零点九”或“公网 IP 已变更为……，出口仍在日本”。IPv4 逐位朗读；IPv6 地址过长，只说明已变为 IPv6 地址。
托盘右键 → **语音播报** 可选“IP 或国家 / 地区变化时”（默认）、“仅国家 / 地区变化时”或“关闭”；“连接异常及恢复时播报”默认开启，可单独关闭，选“关闭”时它也不播报；“试听当前出口”朗读本次确认的结果，菜单底部显示所用语音。

- 连接异常：已确认过连接后，角标变为红色 `×`（链路中断，或连续两轮所测连接均失败）时立即播报“网络连接异常，检测请求均未成功，正在等待重试”；链路中断时即使上次公网 IP 尚未过期也会播报。单轮失败正在复核（黄色）时不播报。连接待确认、仅部分检测可达但没有公网 IP，或启动后尚未确认就失败时，持续约 15 秒仍未确认才播报（失败为上句，其余为“网络连接待确认，暂时无法获取公网 IP，正在等待重试”），因此每次刷新、切网或开机连接 Wi-Fi 的短暂等待不会误报。
- 每次异常只播报一次；重新确认公网 IP 后播报“网络连接已恢复，出口在……”。若恢复时 IP 或国家已变化且按所选模式会播报变化，只播报变化内容。
- 混音：语音使用 SAPI 的 Over 优先级，经 Windows 共享模式音频输出，与正在播放的音乐、视频及其他使用 SAPI 朗读的程序同时发声，不排队等待、不打断也不独占它们。若其他程序以独占模式占用同一音频设备，Windows 不允许任何声音混入，此时播报无声，监控不受影响。
- 与弹窗通知共用判定：启动后的首个结果只作基准；新 IP 的国家尚未识别（灰色地球）时先等待识别，再把 IP 与国旗合并为一次播报。断网、查询失败和暂留国旗不触发播报，也不清除基准，恢复后与上次确认的结果比较。
- 公司代理按目标网站选择出口时，同一国家内的出口 IP 可能来回切换，每次都会播报；如觉得打扰，请选“仅国家 / 地区变化时”。
- 新播报会打断本程序仍在朗读的旧播报，只读最新状态；同时弹出通知时先留约 0.6 秒给提示音。
- 使用 Windows 已安装的离线语音，按晓晓 / 晓伊（若本机通过 SAPI 提供）→ 瑶瑶 → 慧慧 → 其他 zh-CN 女声的顺序选择，语速略慢、音量略低。名称含 Online 的云端语音会被跳过，播报内容（含 IP）不发送给任何语音服务。
- 未安装简体中文女声时不播报，菜单会提示；请在 Windows 设置 → 时间和语言 → 语音 中添加中文语音后重启程序。语音设备异常不影响监控。

## 监听机制与时效

监听网卡地址变化、网络可用性变化和睡眠恢复；合并约 200 毫秒内的事件后发起检查；启动和手动刷新立即发起检查。后台每约 5 秒比较活动 IPv4/IPv6 路由、网卡、DNS 和 Windows 代理设置，发现变化后使旧结果失效并重新检查。这不能发现所有 WFP 过滤规则变化，也不能直接读取 VPN 客户端内部的连接状态。
默认每轮检查完成后等待 5 秒再检查，可改为 10 / 30 / 60 秒。即使选择较长间隔，连接结果临近 30 秒有效期时也会提前复核；部分检测失败时约 5 秒重试。没有本机配置变化事件的公网 NAT / 代理出口变化由轮询发现。
“即时”指事件触发后尽快查询；公网出口没有通用的本机推送事件，因此无法保证零延迟。实际发现时间是等待间隔加请求耗时。

### 链路检测

与 IP / 国家查询独立运行。正常时约每 2 秒对一个目标做一次 TCP 握手：优先 ipv4.icanhazip.com 的解析地址，其次 1.1.1.1、8.8.8.8。握手不发送数据；很多 VPN 会丢弃 ping，所以不用 ICMP。一次失败后改为每 0.5 秒同时握手全部目标复核。同时读取 Windows 访问 1.1.1.1 所走网卡（VPN 在线时即隧道网卡）的单播收发包计数：本程序仍在发包、该网卡却 4 秒以上未收到任何包，即为“只发不收”。

- 一轮失败为“复核中”；连续三轮失败、或失败且已只发不收，为“链路中断”。中断后首次成功为“恢复中”，持续成功 6 秒才恢复正常。
- 只有在当前线路上应答过的目标才计入中断判断，因此一开始就被屏蔽的目标（如部分网络中的 8.8.8.8）不会造成误报。切换线路（VPN 连接或断开）后，重新学习可用目标和耗时基线。
- 握手耗时基线只在线路正常时按中位数学习，单次抖动不会抬高基线。握手超时为基线的 4 倍，限定在 1–3 秒。
- 跟随系统代理且 HTTPS 实际经过代理时，直连握手不能代表代理路径，链路检测暂停判断，只保留 HTTPS 检测。
- 链路检测只说明本机到这些目标的 TCP 路径是否在应答，不代表其他应用的业务接口、UDP/QUIC 或 IPv6 正常。

请求在后台运行。查询与检测复用 HTTPS 长连接，减少每次重新握手；网络配置或代理变化、链路从中断恢复时关闭旧连接，长连接最多使用约 2 分钟后重建。单个请求及每组并发查询默认 4 秒超时；本线路近期成功请求较慢时，放宽到中位耗时的 4 倍，最多 8 秒。IP、备用 IP、国家查询可能分阶段执行，因此一整轮不等于一个超时时长。IP / 国家查询的主服务超过备用等待时间未返回，就启动备用服务（默认 200 毫秒，按近期中位耗时的 1.5 倍调整，最多 1.5 秒）；主服务失败则立即启动备用服务。采用首个通过验证的结果，并取消该组其余请求。
独立的连接检查与 IP / 国家查询并行：同时访问 Cloudflare 的 HTTPS trace 和 ifconfig.me，验证返回内容包含有效公网 IP，两个检测合计使用约 4 秒（慢线路最多 8 秒）的时间预算。两个均成功显示“检测服务可达”，仅部分路径成功显示“部分检测可达”。所测请求均失败时，第一轮显示“检测失败，正在复核”（黄色）并立即请链路检测复核；连续第二轮仍全部失败显示“所测连接未确认”（红色）。即使两个额外检测失败，若本轮 IP 查询成功，也只标记为部分可达，不宣称整台电脑断网。
成功的连接检测仅在同一网络配置、同一代理模式且本轮成功确认同一 IP 时短暂复用，最长 15 秒；失败结果不借用旧成功状态，缓存命中不延长原始检测时间。手动刷新、网络配置变化、IP 变化或 IP 查询失败都会触发重新检测。国家缓存与连接状态分别管理。
没有任何成功路径时，首次失败后约 5 秒重试，连续失败依次退避至 10 / 20 / 40 / 60 秒，不受正常轮询间隔影响；手动刷新和网络事件会重置退避并提前重试。同一时刻只运行一轮；切网会取消旧请求，版本标记阻止旧结果和旧连接检测写回。退出时取消请求并释放托盘图标、GDI 句柄和事件订阅。“重启应用”先完成同样的释放并关闭单实例锁，再启动新实例；新实例最多等待 15 秒让旧实例退出。

## 出口与代理

默认跟随 Windows 系统代理；取消该项后使用本机路由直接发出请求（VPN/TUN 仍可能影响路由）。
每轮重新获取代理配置。IP、国家和连接检查均使用所选代理模式，不会为了让检测成功而自动绕过代理。浏览器插件、应用专用 SOCKS 代理及按域名分流可能产生不同出口，显示结果仅代表本程序查询服务看到的出口。
优先查询公网 IPv4（ipv4.icanhazip.com，慢于 200 毫秒或失败时并发请求同一主机的 Cloudflare /cdn-cgi/trace，采用最先验证成功的结果）；两者失败或达到本组超时后才使用 ifconfig.me 尝试 IPv4/IPv6。
查询服务均按 TCP 连接的来源地址返回 IP，不采信 X-Forwarded-For。Zscaler 等解密 HTTPS 的代理会在请求中插入该头并写入代理前的本机公网 IP，ipify 等采信该头的服务因此报告代理前的地址，而不是网站实际看到的出口。公司代理还可能按目标网站选择不同出口：两个 IPv4 查询共用同一 Cloudflare 主机，经过同一出口，结果代表 Cloudflare 上的网站看到的出口；备用的 ifconfig.me 位于 Google Cloud，可能看到另一个出口。
托盘顶部仅展示本程序的一个当前出口；进程监控窗口独立列出目标进程的双栈结果。切换到 IPv6 备用查询源也可能表现为 IP 变化。
连接角标表示两个 HTTPS 检测服务在本程序所选路径下的可达性，不强制分别验证 IPv4 和 IPv6，也不检查其他应用的登录、聊天、视频等业务接口。即使检测正常，其他应用也可能因进程分流、代理、DNS、地址族或服务端问题而无法连接。

## 进程 IP 监控（VPN 分流 / 代理绕过）

托盘右键 → **监控应用设置**，选择目标 EXE 并勾选“启用探针”；再打开 **进程 IP 监控** 查看独立结果。预置爱奇艺、腾讯视频、优酷视频、QQ音乐、哔哩哔哩、微信 WeChat、ChatGPT、Claude、Grok Bot 的可编辑条目，可增加、删除、改名或停用。预置名称不等于已适配或已实测，默认不启用任何探针。

- 使用“从运行进程选择”绑定真实 EXE，或浏览文件。“匹配已运行的预置应用”只填入检测到的路径，不自动启用探针。应用升级改变安装路径后需重新选择；ChatGPT 的匹配会排除 Codex 的同名可执行文件。
- 按 **完整 EXE 路径 + PID + 进程创建时间** 区分实例。优先探测该 EXE 中拥有已建立非回环 TCP 连接的进程；无此连接时选择最早启动的一个实例。窗口分别列出选中的 PID、IPv4/IPv6、公网 IP、国家、探针模式、时间和失败状态。
- 默认每个结果完成后约 30 秒进入下一轮，可设 15 / 30 / 60 秒；最多同时执行两个探针，排队、超时和国家查询会延长实际间隔。关闭窗口后仍持续监控，退出托盘程序或在设置中停用可停止后续探测。
- 手动刷新、网络地址变化、网络可用性变化及睡眠恢复会使旧结果失效。超过 90 秒的结果标为过期；进程退出、PID 复用、查询失败时不会拿本程序 IP 或旧国家填充。
- **直连（含 VPN）**：进程内 WinHTTP 不使用 HTTP 系统代理，但连接仍受 PrivadoVPN 等产品针对该进程的分流策略影响。**系统代理**：使用 Windows 自动代理配置，不读取目标应用内部的 SOCKS/HTTP 代理设置。

### 探测原理与边界

仅查询 Windows TCP 表只能得到本地端点、对端和所属 PID；本地网卡地址、服务器 IP 或 VPN 路由本身无法证明 NAT / 代理后的公网出口。此功能由配套的 x86/x64 DLL 在目标进程中请求固定 HTTPS 地址，并将结果通过该进程的内存回传给监视器。国家查询由监视器针对这个明确 IP 进行，复用缓存、超时与限流处理，不以监视器自己的出口替代。

IPv4 使用 ipv4.icanhazip.com，失败后尝试同一主机的 /cdn-cgi/trace；IPv6 独立使用 ipv6.icanhazip.com，均按 TCP 连接的来源地址返回 IP。界面保留实际获胜查询源。IPv6 不可用不会抹掉有效 IPv4，反之亦然。结果代表**这个 PID 在所选探针模式下访问测试服务时的出口**，不承诺目标应用访问所有网站、UDP/QUIC、内置代理或其它联网子进程都使用相同出口。共享 WebView、Python 等宿主需自行选择实际联网 EXE；不会自动把其它程序的共享宿主归到某个应用。

进程内加载可能被 DRM、反作弊、沙箱、受保护进程或权限隔离拦截，也可能影响兼容性。探针只允许同一 Windows 用户和会话，不申请调试特权、不提权、不绕过应用保护；访问拒绝会显示原因。当前支持 x64 Windows 上的 x86/x64 进程。加载超时等不可恢复错误在该进程本次生命周期内停止自动重试。

正常完成后卸载 DLL。网络事件、停用或退出时，已在目标内执行的请求会继续完成清理，但结果不再接收；不会强制终止目标线程。如果目标线程长时间无响应，为避免释放仍在使用的内存，DLL/小块参数内存可能保留至目标应用退出；重启目标应用可恢复探测。不要在探针执行期间升级组件，建议先退出监视器并等待在途请求结束。

### PrivadoVPN 实机验收

1. 启动目标应用，在监控设置中绑定它的完整 EXE 并启用，选择“直连（含 VPN）”。
2. 记录该应用测试服务的 IP；在 PrivadoVPN SmartRoute 中对**同一个联网 EXE**设置通过隧道或绕过。
3. 等待 VPN 策略生效，再点“立即重新探测”，比较同一地址族及同一测试服务的 IP。必要时按 VPN 的要求重启目标应用。
4. 切换规则后若返回相同 IP，只能说明该次测试看到了相同出口；检查规则选中的 EXE、子进程和测试站点规则，不从网卡名称猜测结论。
5. 无法连接、IPv6 不可用、权限不足、应用保护等均应显示明确状态。九个预置应用并不保证均允许加载探针，应逐一验证。


## 国家与国旗

对**已获取的明确 IP**调用 ipwho.is 查询国家；慢于 200 毫秒或失败时启动 ipapi.co 备用查询。两个服务均校验响应 IP 与所查询 IP 一致，避免使用另一服务自己的出口地址误配国旗。
成功的国家结果按 IP 缓存 24 小时；仅在新 IP、缓存过期或失败后的重试窗口到来时查询。缓存过期后若国家服务暂时失败，仅对本轮重新确认的同一 IP 沿用不足 7 天的国家缓存，并标注“缓存待更新”、约 5 秒后重试；失败不会延长缓存寿命，也不会把旧 IP 的国家套给新 IP。
普通国家查询错误按服务冷却 5 秒；国家尚未识别时，即使检查间隔设为 30 / 60 秒，也会在本轮完成后约 5 秒再次尝试。HTTP 429 按服务分别尊重 Retry-After（未给出时等待 24 小时），一个服务限流不会阻止备用服务，其间仍持续监控 IP。
252 张国家 / 地区 / 组织旗帜作为 PNG 内嵌在 EXE 中，运行时无需下载；服务返回未知代码时显示代码占位。
地理信息来自第三方数据库，VPN、代理、地址分配变化会影响准确性；国家标识不等于设备物理位置。

## 网络与本地数据

运行程序会向 icanhazip（Cloudflare）/ ifconfig.me 发起 HTTPS 请求以查询本机公网 IP，向 www.cloudflare.com / ifconfig.me 发起 HTTPS 连接检查，并向 ipwho.is / ipapi.co 提交该 IP 查询国家；这些服务会获知请求来源的公网 IP。
链路检测约每 2 秒向 ipv4.icanhazip.com 的解析地址、1.1.1.1 或 8.8.8.8 的 443 端口发起一次 TCP 握手，随即关闭、不发送数据；每 5 分钟及网络变化后解析一次 ipv4.icanhazip.com。
所有查询使用 HTTPS；不发送姓名、设备名、本机私有 IP 或浏览历史。未添加遥测和 IP 历史文件。
设置（含所选应用名称、EXE 路径、启用状态和探针模式）保存至 %LOCALAPPDATA%/IPCountryWatcher/settings.json。进程列表和测量结果只保留在内存，未发送给查询服务；公网查询只发送必要的 IP 请求。国家缓存仅在进程内。
连接诊断在内存保留本次运行最近 120 条事件，从不上传。右键选择“导出连接诊断…”后由用户选择本地保存位置；文本包含程序版本、UTC 时间、检测来源、耗时、失败类别、代理模式及状态变化，不记录具体 IP 历史、响应正文、完整异常或代理凭据。
链路中断、恢复、质量下降和线路切换写入 %LOCALAPPDATA%/IPCountryWatcher/incidents.log，跨重启保留（约 1 MB × 2 个文件，循环覆盖），可随时删除。该日志只含 UTC 时间、事件类别、握手耗时、基线、丢失比例等数字，不含 IP、目标地址或网卡名称；链路中断时附上当时内存中的检测记录（同样不含 IP）。导出连接诊断会附上其中最近 400 行。退出程序后，内存中的记录不保留。
服务需要互联网访问；未配置付费密钥，免费服务限流或不可用时程序会显示状态并自动重试。

6. VPN 显示已连接但隧道不再回包时（例如服务器被阻断），约 4–8 秒内出现红色“链路中断 / 链路无回包”，恢复后约 6 秒取消；导出诊断中的事件日志时间应与 VPN 日志对应。
7. 退出后图标消失；重复启动只保留一个实例。

### 1.0.10（2026-09-24）

[Release](https://github.com/Anna-SAP/IPCountryWatcher/releases/tag/v1.0.10-run35913214150-1) · [PR #3](https://github.com/Anna-SAP/IPCountryWatcher/pull/3) · 短暂查询失败时保持国旗稳定

- **国旗不再频繁闪成灰色地球**：网络事件或单次查询失败时，保留上次确认的国旗最多 2 分钟，并标注“待确认 / 上次”；此期间不能把旧 IP 复制为当前 IP。
- **及时清除旧国旗**：出现未识别的新 IP、Windows 报告网络不可用、切换代理模式或睡眠恢复时立即清除。
- **国家缓存回退**：国家服务暂时失败时，同一 IP 可沿用 7 天内的国家缓存，标注“缓存待更新”并快速重试。
- **更快重试**：首次公网 IP 查询失败约 5 秒后重试，连续失败逐步退避至 60 秒，不受正常轮询间隔影响。

### 1.0.1（2026-09-11）

[Release](https://github.com/Anna-SAP/IPCountryWatcher/releases/tag/v1.0.1-run34607401037-1) · 首个版本

- **系统托盘国旗**：自动获取本程序的公网出口 IP，识别国家 / 地区并显示国旗；252 面旗帜内嵌，运行时无需下载。
- **基本操作**：悬停查看国家代码和公网 IP；右键可刷新、复制 IP、设置检查间隔、切换系统代理、开关变化通知、设置开机启动；双击立即刷新。

- **查询服务**：IP 查询使用 ipify 和 checkip.amazonaws.com，国家查询使用 ipwho.is，国家结果按 IP 缓存 24 小时。
- **自动发布**：GitHub Actions 自动编译、测试并发布安装包和便携版。
